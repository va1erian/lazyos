# Network tooling

Everything that tests or fuzzes LazyOS networking (`docs/networking-plan.md`).
The rule is the one the sound harness follows: **serial markers say when the
guest is done, the verdict is what crossed the wire** (a packet capture), and
every checker has tests that prove it fails when it should.

| Layer | What | Run |
|---|---|---|
| Host unit | `framering`, `virtio-net`, `nicdrv` (the driver core against a fake device and a hostile client), `netpolicy`, `virtio` (queue, incl. the 256-entry cap), the generated `os.lazy.net.nic.v1` stubs | `cargo test -p framering -p virtio-net -p nicdrv -p netpolicy -p virtio -p messenger-generated` |
| Seeded fuzz | The same entry points the cargo-fuzz targets use, driven by a PRNG over many seeds, inside plain `cargo test` (any platform) | `cargo test -p framering -p virtio-net -p nicdrv fuzz::` |
| Replay a failure | A failing seed prints `FUZZ_SEED=0x...`; set it to rerun exactly that case | `FUZZ_SEED=0x6a04526241fcd766 cargo test -p framering clean_scripts` |
| Longer soak | More seeds per test | `FUZZ_CASES=20000 cargo test -p framering -p virtio-net -p nicdrv fuzz::` |
| Coverage-guided fuzz | libFuzzer via `cargo-fuzz`, Linux (CI runs it for a bounded time) | `cargo install cargo-fuzz`, `mkdir -p fuzz/corpus/framering`, then `cargo fuzz run framering --fuzz-dir fuzz fuzz/corpus/framering fuzz/seeds/framering -- -max_total_time=60` |
| Harness unit | The pcap judge must fail when it should: a missing reply, a wrong payload, the wrong order, a truncated capture, an empty file, frames outside the length policy | `python tools/net/test_analyze_pcap.py` |
| End to end | Build with `LAZYOS_NET=1`, boot headless QEMU with a virtio-net card and a packet capture, judge the capture | `python tools/net/run.py` |
| Seed corpus | Checked in under `fuzz/seeds/<target>/`, generated by a deterministic script (libFuzzer grows the git-ignored `fuzz/corpus/`) | `python fuzz/gen_corpus.py` (`--check` in CI) |

## Fuzzing design

Each fuzzed library exposes one entry point that takes `&[u8]`, reads it as a
script of operations against a reference model, and panics on a violated
invariant (`libs/framering/src/fuzz.rs`, `libs/virtio-net/src/fuzz.rs`, behind
the `fuzz` cargo feature or `cfg(test)`). Two things drive it:

* the **seeded tests** in the same file, using `libs/fuzzkit` (a small PRNG and
  a driver that prints the failing seed), so `cargo test` alone exercises the
  code on every platform, Windows included;
* the **cargo-fuzz targets** in `fuzz/fuzz_targets/`, which call the same
  function, so libFuzzer's coverage feedback works on exactly the code the tests
  check. `fuzz/` is outside the OS workspace, so local development never needs
  libFuzzer.

A crash found by libFuzzer is a file under `fuzz/artifacts/<target>/`. Copy it to
`fuzz/regressions/<target>/` (checked in) once fixed: the `checked_in_corpus_replays`
tests run every file there, so the bug stays fixed under plain `cargo test`.

`framering` is checked two ways: while nothing has scribbled on the shared
memory, every result must match the model exactly (order, bytes, `Full` exactly
when full, wake-ups exactly when armed); once a hostile peer has scribbled on an
index, a length or a payload, only safety is checked (no panic, delivered
lengths in range, poison is sticky, guard pages either side of the region never
written). `virtio-net` feeds random device configuration, receive completions
with hostile lengths, packet headers and settings to the parsers.

## The end-to-end harness

```bash
python tools/net/run.py                            # build, boot, capture, verify (about 15 s on WHPX/KVM)
python tools/net/run.py --no-build --accel none    # reuse target/lazyos.img, force TCG
python tools/net/run.py --services                 # init supervises netdrv as the unprivileged _net user (uid 902)
python tools/net/run.py --machine q35 --virtio-disk
python tools/net/run.py --poll                     # interrupts off: the driver must poll and still pass
python tools/net/run.py --no-device                # -nic none: the driver prints NETDRV:NODEV and idles
python tools/net/analyze_pcap.py shots/net/net.pcap --min-arp-pairs 42 --expect-probe   # judge a capture alone
```

QEMU is discovered like the other tools (`--qemu`, then `PATH`, then
`C:\Program Files\qemu` on Windows). Outputs go to `shots/net/` (`serial.log`,
`net.pcap`); `shots/` is git-ignored. `python tools/run_demo.py --net` boots the
same image interactively; `nicctl` then runs from the shell.

The image is built with `LAZYOS_NET=1`, which embeds `NETDRV.ELF` and
`NICCTL.ELF` and starts `netdrv demo=1` (from the kernel, or from `init`'s
manifest with `LAZYOS_SERVICES=1`). The guest prints, in order:

| Marker | Meaning |
|---|---|
| `NETDRV:CARD mac=... link=... irq=armed\|polling` | the device was claimed and brought up |
| `NET:NIC:PASS ... arp_reply_from=...` | the driver broadcast an ARP request for the gateway through its own engine and got the reply |
| `NET:IRQ:PASS delivered=N` | the armed INTx line delivered interrupt messages (`NETDRV:IRQ:POLLING` instead when the line is not routable or `--poll`, which the harness reports but accepts) |
| `NETDRV:READY` | `os.lazy.net.nic.v1` is registered |
| `NICCTL:INFO:PASS` | `nicctl` read the card through the interface |
| `NICCTL:ARP:PASS` | a real client attached rings and exchanged ARP with the gateway |
| `NICCTL:PROBE:PASS checks=40` | malformed and hostile requests were all refused correctly and the frame-length policy held; the driver survived a client that corrupted its own ring |
| `NICCTL:INTRUDER:PASS checks=5` | a second task was refused on the owner's ring |
| `NICCTL:SOAK:PASS iterations=40` | 40 attach/exchange/detach cycles leaked no handle, endpoint, buffer or mapping |

The harness waits for all of them (or any `FAIL`), stops QEMU through QMP so the
capture is closed, and then **the capture decides**: 42 complete ARP exchanges
with the gateway (request then reply, addressed to the guest, sender fields
consistent), no frame shorter than 14 or longer than 1514 bytes anywhere, and
the probe's boundary frames on the wire (exactly 14 and 1514 bytes, payload
intact, none of 13 or 1515). With `--services` it also requires
`NETDRV:CRED uid=902 caps=0x100`.

`analyze_pcap.py` (with `pcap.py`, both stdlib only) is strict about the capture
itself: an empty file, a bad header or a record cut short is an error, never
"fewer packets", so a killed emulator cannot become a pass.

Later stages add to this file: the `netstack` frame fuzzing, `netd`'s probe and
soak modes, and the DHCP and ping checks (N2).
