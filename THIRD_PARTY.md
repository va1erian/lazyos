# Third-party code and data

LazyOS is GPL-3.0-or-later ([`LICENSE`](LICENSE)). This file is the register
of third-party material that is **taken into the tree or the image** and that
needs a licence decision: vendored or derived source, and binary blobs. It
exists because the Wi-Fi work ([`docs/wifi-plan.md`](docs/wifi-plan.md) section
4, option A) will be the first time a native service carries code derived from
another project.

Not repeated here, because they already have a home:

- Cargo dependencies: every crate is MIT, Apache-2.0, BSD, Zlib or Unlicense
  (see the README's License section); the TLS stack's tree is enforced by
  `python tools/nettls/licenses.py`. Crypto crates are listed below only
  because `libs/crypto` is where they are chosen.
- Fonts, samples and wallpapers: one line each in
  [`assets/manifest.txt`](assets/manifest.txt), licence texts beside them.
- Doom, Freedoom and doomgeneric: [`games/doom/NOTICE`](games/doom/NOTICE).

## The rule

Code may be copied or derived from only if its licence can be absorbed by
GPL-3.0-or-later:

| Accepted | Taken under |
|---|---|
| ISC, BSD-2-Clause, BSD-3-Clause, BSD-3-Clause-Clear, MIT | as is |
| `GPL-2.0 OR BSD-3-Clause` (dual) | the BSD side |
| GPL-2.0-or-later, LGPL-2.1-or-later | GPLv3 |
| `MIT OR Apache-2.0` (Rust crates) | MIT |

Refused: **GPL-2.0-only** code (Linux `mac80211`, `cfg80211`, `mt7601u`,
`mt76x0`, `rtl8xxxu`, ...), Apache-2.0-only code (GPLv3-compatible, but not
GPLv2-compatible, which the TLS stack and LazyWeb require; see
`tools/nettls/licenses.py`), and anything without a licence. The working rule that follows: **never read GPL-2.0-only code "for
reference" while writing our own.** Where Linux is the only place a behaviour
is documented, use the permissive trees (the `mt76` driver, OpenBSD and
FreeBSD `net80211`, hostap) as the specification.

Firmware blobs are not source and are never linked into a binary or
`include_bytes!`'d (that is what their licences forbid); each is a file in the
image under its own licence text. Every entry below records its origin
(project and commit or version), its licence and the files it touches.

The rows from zlib to the Liberation font are the WebKit dependency bundle
(`tools/webkit`, [`README`](tools/webkit/README.md)): static libraries that
`LAZYOS_WEBKIT_DEPS=1` images link into `/system/bin/depsproof` and that
WebKit (LGPL-2.1) links statically into the port's programs
(`/system/bin/webprocess` and `networkprocess` with `LAZYOS_LAZYWEBPLUS=1`,
`LAZYOS_WEBD=1` or `LAZYOS_WEBKIT_PORT=1`, `webkit-smoke` with `LAZYOS_WEBKIT_PORT=1`, and the
browser's `lazywebplus-app` with `LAZYOS_LAZYWEBPLUS=1` and webd's `webd-app` with
`LAZYOS_WEBD=1`; libwpe and glstub only there).
WebKit 2.54.1 itself has a row: the WebKitGTK tarball (LGPL-2.1-or-later AND
BSD-2-Clause) is statically linked into those binaries. They are built from the
pinned, hash-checked archives named in `tools/webkit/wkpins.py`; none is copied
into the tree.

`lazywebplus-app` (LazyWeb+, `os.lazy.lazywebplus`, `LAZYOS_LAZYWEBPLUS=1`,
[`docs/lazywebplus.md`](docs/lazywebplus.md)) is this repository's own code on top of
WebKit: the C++ UI process (`webkit/port/app`) with LazyWeb's window
(`xui-app/webplus`, plus the `xui-webkit` seam it links). The program statically links
the WebKit libraries above, so it is LGPL-2.1-or-later and GPL-3.0-or-later together.
LazyWeb's rule for what is linked into its window holds: `python
tools/nettls/licenses.py --lazywebplus` passes over the window's Cargo tree with one
waiver, `unicode-linebreak` (Apache-2.0 only, in every xui app through xui-canvas).
The window crates are declared `GPL-2.0-only OR GPL-3.0-or-later` and the program, which
links OpenSSL (Apache-2.0, below) through WebKit's curl, is distributed as
GPL-3.0-or-later: a GPL-2.0-only program cannot carry OpenSSL.

Two rows are exceptions to the rule above, on purpose:

- **OpenSSL is Apache-2.0**, which GPLv3 absorbs but GPLv2 does not. It is
  allowed only inside the WebKit bundle (LGPL-2.1 WebKit's curl port and
  SubtleCrypto call its API) and **must never be linked into LazyWeb**
  (GPL-2.0-only, `docs/lazyweb.md`) or the `nettls` TLS stack.
- **libpsl is MIT, but its embedded public-suffix list is MPL-2.0**
  (`MIT AND MPL-2.0`); MPL-2.0 section 3.3 lets it combine with (L)GPL code.

`python tools/webkit/licenses.py` checks these rows against `wkpins.py`
(`--rows` prints them), accepts only licences an LGPL-2.1 binary can absorb,
and fails if LazyWeb's sources use the bundle or depend on OpenSSL.

A row is updated, with the pinned commit and the file list, in the same
commit that brings the code or blob in. "Not yet taken" rows are promises of
where the material is expected to come from, not permission to copy it.

`python tools/wifi/licenses.py` checks the Wi-Fi rows against the code: the
`libs/rtw88` row names `rtw88::UPSTREAM`, every firmware file of
`tools/firmware/manifest.txt` has a row with its digest and commit, and every
crate linked into the Wi-Fi crates has a GPLv3-compatible licence.
